Работа продолжает [main.cpp](../../main.cpp) общего проекта [CompGraphics](../../CMakeLists.txt). Существующие текстуры и режимы смешивания 12-й недели сохранены. Добавлены нормали, освещение и переключаемые эксперименты. Исходный код остаётся в корне проекта, отчёт и кадры находятся в `docs/week13/`, как материалы предыдущей недели.

## Запуск

Из папки `/Users/nurdaulet/CompGraphics`:

```bash
cmake --build build --target cg
./build/bin/cg
```

По умолчанию источник света движется по окружности радиуса 1.5 на высоте 1.0; кубы неподвижны, чтобы движение света было заметно. Свет обозначен маленьким белым кубом. Для начала выбран материал ящика (`blend = 0`), правильные нормальные матрицы и ограничение диффузной составляющей через `max`.

## Управление

| Клавиша | Действие |
| --- | --- |
| J / K | Следующий / предыдущий эксперимент, номер и название видны в заголовке |
| O / L | Увеличить / уменьшить ambient со скоростью 0.3 в секунду; пределы 0…0.5 |
| H | Восстановить орбитальный свет, правильное освещение, материал ящика и ambient 0.1 |
| V | Включить / выключить вращение кубов в режиме орбитального света |
| R | Сбросить камеру в `(0,0,3)` |
| P | Состояние камеры, выбранный эксперимент и ambient |
| Q | Удерживать для ортографической проекции; O освобождена для ambient |

Остальное управление сохранено: WASD, мышь, колесо, Space / Left Shift, Left Ctrl, 1/2/3 для чувствительности, стрелки для `blend`, 4–0 для смешивания текстур, Page Up / Page Down для скорости вращения, B для белого фона, Esc для выхода. F1/F2/F3 остаются историческими экспериментами 12-й недели; для задания 13-й недели они не нужны.

Порядок экспериментов J/K:

| Номер | Режим | Условия |
| --- | --- | --- |
| 1 | basic Lambert | Неподвижный свет `(1.2,1,2)`, правильная нормальная матрица |
| 2 | orbiting light | Свет `(1.5 sin(t), 1, 1.5 cos(t))`, uniform обновляется каждый кадр |
| 3 | NO MAX | Намеренно убран max, ambient 0.4, свет сзади `(0,0,-3)` |
| 4 | WRONG normal matrix | Первый куб: `S(1,2.5,1) * Rz(45°)`, нормаль через `mat3(model)` |
| 5 | inverse transpose | Тот же первый куб и свет, нормаль через обратную транспонированную матрицу |
| 6 | ambient control | Неподвижная сцена для сравнения ambient 0, 0.1 и 0.5 |
| 7 | Gouraud | Освещение по вершинам, свет `(0,0,1.2)` |
| 8 | Phong shading | Освещение по фрагментам, та же геометрия и свет `(0,0,1.2)` |

При выборе режима ambient устанавливается в 0.1, в режиме 3 — в 0.4; затем его можно менять O/L. В режимах 4/5 автоматически устанавливается одинаковая боковая камера `(3.5,2,6)`, направленная в начало координат: растянутый куб помещается целиком и видны грани, нормали которых меняются. В режимах 7/8 автоматически устанавливается одинаковая фронтальная камера `(0,0,3)`; лампа скрыта, чтобы не закрывать центр грани. В остальных режимах камера сохраняет положение. Для возврата к исходному виду можно нажать R.

В неправильных режимах 3/4 ошибка включается намеренно. H возвращает корректные `max` и нормальную матрицу. Для чистого сравнения использовать одинаковый материал: H восстанавливает ящик, а J/K меняют только эксперимент освещения и предусмотренную для пары камеру.

## Реализация

Вершина содержит восемь float: XYZ, UV, normal XYZ. В трёх `glVertexAttribPointer` stride равен `8*sizeof(float)`. Атрибут нормали имеет location 2, размер 3, offset `5*sizeof(float)` и включён через `glEnableVertexAttribArray(2)`.

Во всех шести вершинах каждой грани записана одна и та же внешняя единичная нормаль. Геометрический порядок CCW сохранён. `FragPos` получается через `uModel`; нормаль преобразуется в мировое пространство. Перед отрисовкой каждого куба отдельно вычисляется `transpose(inverse(mat3(model)))`; исключение — первый куб в намеренно неправильном режиме 4. Старый Z-fighting режим также получает свою нормальную матрицу для каждого объекта.

В обычном фрагментном освещении:

```glsl
vec3 norm = normalize(Normal);
vec3 lightDir = normalize(lightPos - FragPos);
float diffuse = max(dot(norm, lightDir), 0.0);
vec3 lighting = (ambientStrength + diffuse) * lightColor;
```

Полученное освещение умножается на RGB материала; альфа материала сохраняется. Все величины освещения находятся в мировом пространстве. Нормальная матрица — mat3, поэтому перенос не применяется к направлению нормали. Uniform-локации кэшируются до основного цикла.

## Ответы для защиты

### 1. Движущийся свет и камера

При неподвижных источнике и объекте освещение одной и той же точки поверхности не зависит от положения камеры: в формуле Lambert есть нормаль и направление на свет, но нет направления на наблюдателя. При движущемся источнике свет продолжает меняться со временем независимо от перемещения камеры. Для проверки именно влияния камеры нужно выбрать неподвижный свет, режим 1.

От камеры зависела бы зеркальная составляющая, specular: направление отражения сравнивается с направлением на наблюдателя. На этой неделе specular ещё не добавлена. Название «Phong shading» здесь означает расчёт освещения по фрагментам с интерполированными нормалями, а не наличие полной модели отражения Фонга с бликом.

### 2. Зачем нужен max

При белом свете, ambient 0.4 и `dot = -1`:

```text
ambient + diffuse = 0.4 + (-1) = -0.6
```

Положительная RGB-текстура после умножения тоже даёт отрицательные компоненты. При записи в обычный нормализованный framebuffer они ограничиваются снизу нулём. В результате сторона чёрная, включая потерянный вклад ambient. С `max(dot,0)` отрицательный diffuse становится нулём до сложения, поэтому остаётся ambient 0.4. Сохранены обе версии с одним положением света и одинаковой камерой.

### 3. Расчёт нормальной матрицы

Исходная правая нормаль: `n = (1,0,0)`. Матрица модели `M = S * R`, где `S = diag(1,2.5,1)`, а `R` — поворот вокруг Z на 45°. GLM сначала применяет R, затем S.

Неправильное преобразование:

```text
R*n = (sqrt(2)/2, sqrt(2)/2, 0)
S*R*n = (0.7071068, 1.7677670, 0)
normalize(...) = (0.3713907, 0.9284767, 0)
```

Правильное преобразование:

```text
M^(-T) = (S*R)^(-T) = S^(-1)*R
M^(-T)*n = (0.7071068, 0.2828427, 0)
normalize(...) = (0.9284767, 0.3713907, 0)
```

Скалярное произведение нормализованных результатов равно `20/29 ≈ 0.6896552`. Угол `acos(20/29) ≈ 46.3972°`. Эти значения также вычислены в проверке C++.

Обратная транспонированная матрица сохраняет перпендикулярность нормали преобразованной касательной: `(M^(-T)n)·(Mt) = n·t = 0`. Обычное умножение на M при неоднородном масштабе этого не гарантирует. Если scale убрать, остаётся ортогональная матрица поворота: `R^(-T) = R`, поэтому обе версии совпадут.

Для визуального сравнения нужен ракурс, где видны боковые грани. При взгляде строго вдоль Z передняя нормаль `(0,0,1)` в данном примере не меняется ни одним из двух преобразований, поэтому только эта грань разницу не показывает.

### 4. Что имитирует ambient

Ambient грубо приближает непрямое освещение: свет, многократно отражённый окружением. При ambient 0 неосвещённые напрямую стороны полностью чёрные, хотя в обычной комнате получают отражённый свет. При ambient 0.5 тёмные стороны становятся слишком яркими, относительный контраст уменьшается, форма выглядит более плоской.

Точный расчёт требовал бы учитывать геометрию окружения, видимость, материалы и множество отражённых путей света. Постоянный ambient значительно дешевле, но не моделирует эти эффекты пространственно.

### 5. Гуро и расчёт по фрагментам

Гуро вычисляет освещение только в вершинах, затем интерполирует результат. Максимум внутри большой грани может отсутствовать во всех углах, поэтому интерполяция его не восстановит. В нашем примере точечный свет находится перед центром грани, где фрагментный Lambert даёт более высокую яркость, чем линейная интерполяция значений в углах.

При уменьшении треугольников методы приближаются друг к другу. Точное совпадение возможно, когда освещение постоянно или линейно по треугольнику; например, у плоской грани с постоянной нормалью и направленным светом. Дополнительная тесселяция обычно уменьшает ошибку Гуро, но сама по себе не гарантирует математически точного равенства.

У симметричной передней грани и источника точно перед её центром все четыре угловых значения одинаковы: Гуро может дать равномерно тёмную грань, без обязательной диагональной полосы. Поэтому критерий сравнения — потеря центрального максимума; полоса, упомянутая в PDF, возникает не при любой конфигурации.
