# 12-я неделя: две текстуры и смешивание

Приложение продолжает общий проект: [main.cpp](../../main.cpp), [CMakeLists.txt](../../CMakeLists.txt), [assets](../../assets). Камера, пять кубов, UV, тест глубины, culling и mipmap сохранены. Материалы отчёта находятся в этой папке, исходный код остаётся в корне проекта, как на предыдущих неделях.

`pattern.png` и `logo.png`, упомянутые как приложения к заданию, не были предоставлены. В проект добавлены собственные тестовые изображения: узор RGB 512×512 и логотип-призма RGBA 512×512 с прозрачным фоном и мягким краем. При получении учебных изображений достаточно заменить файлы и перезапустить программу.

## Запуск и управление

Из корня проекта:

```bash
cmake --build build --target cg
./build/bin/cg
```

| Клавиша | Действие |
| --- | --- |
| ↑ / ↓ | Увеличить / уменьшить `blend` со скоростью 0.5 в секунду, пределы 0…1 |
| 4 | Линейное смешивание `mix(a, b, blend)` |
| 5 | Умножение `a * b` |
| 6 | Сложение `a + b` |
| 7 | Сложение с ограничением `clamp(a + b, 0, 1)` |
| 8 | Логотип поверх ящика: `mix(base, decal, decal.a)` |
| 9 | Переход снизу вверх по `vTexCoord.y` |
| 0 | Переход через `smoothstep(0.3, 0.7, vTexCoord.y)` |
| F1 | Включить / выключить ошибку текстурных единиц, задание 1 |
| F2 | Включить / выключить передачу ID вместо единицы, задание 2 |
| F3 | Восстановить правильные привязки, линейный режим и `blend = 0.5` |
| Page Up / Page Down | Скорость вращения кубов; стрелки освобождены для `blend` |
| P | Состояние камеры, коэффициент, режим, настройки эксперимента и привязки текстур |

На клавиатуре Mac для F1–F3 может потребоваться Fn. WASD, мышь, колесо, Space / Left Shift, Left Ctrl, R, I, 1/2/3, B, O и Esc работают как прежде. R сбрасывает камеру, F3 — настройки смешивания. Переключатели F1/F2 срабатывают один раз за нажатие, взаимоисключаются и переводят шейдер в линейный режим.

Изначально выбран линейный режим, `blend = 0.5`, оба эксперимента выключены. Для крайних значений удерживать ↓ или ↑ до 0 либо 1; значение видно в заголовке окна. Коэффициент `blend` используется только в линейном режиме. Умножение, сложение, альфа и UV-переходы имеют собственные формулы.

## Задание 1: перепутанные текстурные единицы

Нормальная привязка: sampler `texture1 = 0`, sampler `texture2 = 1`; на единице 0 находится ящик, на единице 1 — узор. В режиме 8 на единицу 1 вместо узора привязывается логотип. Vertex shader и UV для всех режимов одни и те же.

F1 воспроизводит два последовательных `glBindTexture` без переключения единицы между ними. Для воспроизводимости эксперимент начинает с активной единицы 0 и пустой единицы 1. После второго bind:

```text
sampler texture1 = 0 -> unit 0 -> pattern (ID 2)
sampler texture2 = 1 -> unit 1 -> 0, текстура не назначена
```

При `blend = 0` виден узор. При `blend = 1` кубы чёрные: на проверенном драйвере чтение незаполненной единицы даёт чёрную текстуру. Промежуточные значения затемняют узор. Драйвер Apple также выводит предупреждение о недоступной текстуре; оно ожидаемо только в намеренно сломанном режиме.

В PDF фраза «в обоих случаях tex2» противоречит приведённой формуле `mix` и последующему пояснению о чёрном втором sampler. Снимки и журнал показывают фактический результат на GPU. При простом удалении `glActiveTexture` из другого кода результат также зависит от того, какая единица была активна до двух bind; поэтому начальное состояние здесь задано явно. F1 повторно или F3 восстанавливает правильный код привязки.

## Задание 2: ID текстуры вместо номера единицы

В проверочном запуске на Apple M4 получены:

```text
tex1 = 1 tex2 = 2 logo = 3
```

Это фактические ID из [журнала проверки](validation.txt), а не обещание таких же ID в любом OpenGL-контексте.

F2 намеренно передаёт `tex2` в sampler `texture2` вместо числа `1`. При ID 2 sampler читает единицу 2, которая в нашем двухсамплерном шейдере не используется и не заполнена. На `blend = 1` видны чёрные кубы. Привязка самого узора при этом правильная, на единице 1, но sampler смотрит на другую единицу.

Если ID случайно равен 1, ошибочный код может выглядеть рабочим. После изменения порядка создания текстур совпадение исчезает. ID — имя объекта, номер единицы — индекс места его привязки; между ними нет гарантированной связи. Добавление третьего объекта также не гарантирует изменение ранее выданных ID: важно именно распределение объектов при их создании. ID вне допустимого диапазона sampler может привести к ошибке рисования, а не просто к чёрной картинке.

## Задание 3: четыре способа смешивания

Для каждого цветового канала `0 ≤ a, b ≤ 1`. Поэтому `a*b ≤ a` и `a*b ≤ b`: умножение затемняет или оставляет цвет прежним. Белый множитель не меняет цвет, чёрный обнуляет его. Это подходит для грязи, пятен и затемняющих масок.

Сложение увеличивает яркость, поэтому подходит для свечения, искр и пламени. Компоненты могут превысить 1. Явный `clamp` обрезает их до 1, но не восстанавливает потерянные различия яркости.

На обычной нормализованной цели рендеринга RGBA8 результат `a+b` уже ограничивается диапазоном 0…1 при записи. Поэтому режимы 6 и 7 на сохранённых кадрах совпадают; явный `clamp` не устраняет пересвет. На цели с плавающей точкой разница появляется: без `clamp` можно сохранить HDR-значения выше 1 для дальнейшей обработки.

## Задание 4: альфа логотипа

В режиме 8 второй sampler читает `logo.png` с четырьмя каналами. Отдельное OpenGL-смешивание с фоном сцены здесь не требуется: базовая текстура и логотип объединяются внутри фрагментного шейдера.

| Альфа логотипа | Что получается |
| --- | --- |
| 0 | Только базовый ящик |
| 1 | Только цвет логотипа |
| Между 0 и 1 | Смесь ящика и логотипа, мягкий край |

У тестового логотипа проверены 197351 полностью прозрачный, 58883 непрозрачных и 5910 промежуточных пикселей. Числа относятся к добавленному тестовому изображению, не к отсутствующему исходному приложению к PDF.

## Задание 5: пространственный переход

В режиме 9 коэффициент равен `vTexCoord.y`: внизу грани виден ящик, вверху — узор, между ними плавная линейная смесь. Режим 0 использует `smoothstep`: до 0.3 остаётся ящик, после 0.7 — узор, внутри этого диапазона происходит плавный кубический переход с нулевой производной на границах.

Это применяется для снега по высоте, мокрых участков, изменения материала ландшафта и переходов между поверхностями. Для неровной границы, например травы и камня, коэффициент можно брать из отдельной маски смешивания либо из процедурного шума. Одна UV-развёртка при этом может использоваться для всех текстур.

## Проверка и снимки

Приложение собирается с существующим CMake. Дополнительно выполнен рендер без оконного интерфейса в контексте OpenGL 4.1 Metal на Apple M4, с теми же GLSL-строками, `loadTexture()`, `bindSceneTextures()`, вершинами, пятью позициями кубов и матрицами камеры из `main.cpp`. Для сопоставимости всех кадров угол вращения зафиксирован на состоянии времени 0.7 с. Это сохранённые GPU-кадры, без снимка интерфейса терминала или окна.

Проверены компиляция и линковка GLSL, загрузка всех трёх PNG, mipmap вплоть до 1×1, три случая альфы, соответствие пикселей формулам `mix`, умножения и сложения, UV-режимы и обе намеренные ошибки. Привязки и ID сохранены в [validation.txt](validation.txt). Предупреждение в начале журнала относится к намеренному обращению к незаполненному sampler.
